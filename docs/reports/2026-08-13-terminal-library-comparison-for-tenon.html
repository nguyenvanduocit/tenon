Library-only · tối ưu lợi ích cho Tenon · 13/08/2026

Ghostty và Alacritty chỉ so được công bằng sau khi chốt đúng boundary

ghostty-internal là full terminal stack có hosted renderer; libghostty-vt và alacritty_terminal là terminal cores. Tenon hiện cần full stack. Vì vậy, thay Ghostty bằng crate Alacritty không phải đổi parser — đó là quyết định để Tenon tự sở hữu renderer, font, AppKit input bridge và ABI Rust.

Đánh giá dựa trên source upstream hiện tại, artifact Tenon đang pin và contract TerminalSurface trong live tree. Không xét tabs, themes hay trải nghiệm app độc lập.

Quyết định tối ưu cho Tenon

Giữ ghostty-internal làm backend production; dùng libghostty-vt làm hướng theo dõi dài hạn; không chuyển sang alacritty_terminal ở kiến trúc hiện tại.

alacritty_terminal là một Rust crate tốt cho VT state + PTY, nhưng thiếu renderer/font/window/input host và C ABI. libghostty-vt có C ABI, render-state/damage/snapshot rất phù hợp Swift hơn, nhưng thiếu PTY và full renderer. Chỉ ghostty-internal đang giao cho Tenon toàn bộ terminal surface từ PTY đến Metal trong một integration đã chạy.

Production hôm nayghostty-internal, kèm facade + pin + compatibility tests.
Nếu Tenon muốn tự viết rendererƯu tiên đánh giá libghostty-vt trước Alacritty vì C ABI và render-state API.
Vai trò tốt nhất của AlacrittyReference/benchmark oracle cho VT + PTY, không phải backend drop-in.

Boundary Tenon thực sự đang mua từ library

Tenon không chỉ cần parser biến bytes thành cells. Backend còn phải là một view native, sở hữu shell/PTY, xử lý AppKit input/IME, render bằng GPU, và xuất semantic/process state cho Agent Lens cùng CLI.

Ba lựa chọn library thực tế

So sánh đúng không phải Ghostty vs Alacritty thành hai cột. Ghostty upstream có hai boundary khác nhau; mỗi boundary giải quyết một bài toán khác.

Full stack · đang dùng

ghostty-internal

  • C ABI cho app/config/surface/input/cells/process.
  • PTY + font + Metal renderer + hosted macOS NSView.
  • Tenon pin XCFramework từ Muxy fork, kiểm checksum và provenance.
  • Giá phải trả: upstream nói rõ internal, tailored cho macOS app, không dành cho external use.G1
VT core · public direction

libghostty-vt

  • C API: terminal state, cells, effects, selection, render state, formatter, snapshot, Kitty graphics.
  • Dirty tracking theo frame/row và two-phase update để giảm thời gian giữ terminal lock.G3
  • Build được static/shared/WASM/XCFramework universal.G4
  • Thiếu: PTY/session, font rasterization và GPU/native view.
  • Giá phải trả: header vẫn cảnh báo incomplete/WIP/unstable.G2
Rust terminal core

alacritty_terminal 0.26.0

  • Published Apache-2.0 crate: Term, Grid, selection, vi mode, PTY/TTY và I/O event loop.A1
  • RenderableContent + TermDamage cho custom renderer.A2
  • PTY implementation có child-exit events và macOS login-shell path.A4
  • Thiếu: public renderer/font/window/input library và C ABI.
  • Giá phải trả: Swift bridge phải bọc Rust generics, traits, Arc<FairMutex> và callback ownership.

Chi phí sở hữu được chuyển đi đâu?

Hiệu năng: lợi ích thật nằm ở boundary, không nằm ở tên library

Cả hai terminal cores đều có damage tracking và cố giảm thời gian giữ terminal lock. Không có cơ sở để kết luận thay parser sẽ làm Tenon nhanh hơn; bottleneck đã biết của Tenon nằm ở cách host đọc màn hình trên main actor.

libghostty-vt

Render-state API tốt cho custom renderer

  • Dirty state global + per-row.
  • Two-phase begin/end update để release terminal lock trước khi hoàn tất frame.
  • Caller-driven scrollback compression, không tự tạo background thread.
  • C API cho cell iteration và render state, giảm bridge complexity với Swift.
alacritty_terminal

TermDamage + PTY event loop đã trưởng thành

  • TermDamage::Full/Partial và per-line bounds.
  • RenderableContent chứa grid iterator, selection, cursor, colors và modes.
  • PTY I/O chạy trên thread riêng, dùng FairMutex<Term> và wakeup event.
  • Nhưng đưa các primitive này qua C/Swift sẽ cần snapshot ABI do Tenon định nghĩa.
Cơ hội tối ưu có ROI cao hơn engine swap: GhosttySurface.screenFingerprint hiện gọi ghostty_surface_read_cells và hash toàn bộ viewport 5 lần/giây cho mỗi pane trên main actor. Trước khi đổi library, nên đo và nếu còn hot, thêm một content-generation/damage signal nhỏ vào Tenon-owned Ghostty facade/fork để bỏ full-grid scan khi surface không đổi. Cả Ghostty VT và Alacritty core đều chứng minh underlying engine đã có khái niệm damage; Alacritty không có lợi thế độc quyền ở đây.
Không khuyến nghị chạy song song hai VT cores. Feed cùng PTY bytes vào ghostty-internal để render và một core khác để đọc semantics sẽ nhân đôi terminal state/scrollback, tạo nguy cơ divergence ở width, OSC, resize và shell effects, đồng thời tăng CPU/RAM đúng chỗ Tenon đang muốn tối ưu.

Chiến lược tối đa lợi ích, tối thiểu ownership

Giữ full-stack boundary. TerminalSurface nên tiếp tục abstract một hosted terminal session, không hạ xuống parser boundary. Đây là boundary sát nhu cầu sản phẩm Tenon nhất.
Đặt Tenon-owned compatibility facade trước ghostty-internal. Chỉ export đúng semantics Tenon dùng, giấu struct/layout upstream, kiểm version/build provenance ở runtime hoặc build time, và gom adaptation khi Ghostty đổi ABI.
Sở hữu artifact pipeline. Thay soft-fork artifact Muxy bằng pipeline Tenon-controlled trên upstream pin/fork; giữ universal XCFramework, checksums, header sync và rollback staging hiện có.
Tối ưu observation trước renderer. Profile cell reads, fingerprint, scrollback paging và 200 ms activity loop; ưu tiên generation/damage callback, cache fingerprint và background-safe snapshot thay vì thay emulator core.
Dùng libghostty-vt làm đường thoát chiến lược. Theo dõi versioned release và API stability. Chỉ spike custom renderer nếu Tenon thực sự cần quyền kiểm soát cells/layout/rendering mà full Ghostty surface không thể cung cấp.
Không port sang Alacritty nếu không có trigger mới. Trigger hợp lệ là Windows host, Ghostty full API bị đóng, hoặc benchmark production + prototype chứng minh chênh lệch đáng kể sau khi tính cả FFI/renderer. “Crate public hơn” chưa đủ.

Giới hạn

Không có runtime benchmark trong quyết định này

Không có một renderer chung nên benchmark parser-only không đại diện cho Tenon. Một so sánh production cần cùng PTY replay, font, renderer, Swift bridge, activity observation và process semantics. Đề xuất ưu tiên instrument current path trước.

API status có thể thay đổi

Cả public libghostty C API lẫn Alacritty crate đều pre-stable theo những cách khác nhau. Báo cáo chốt source ngày 13/08/2026; versioned libghostty release hoặc public Alacritty renderer sẽ là trigger hợp lệ để đánh giá lại.

“Không có” nghĩa là library không giao capability đó

Tenon luôn có thể fork app code hoặc tự viết thêm. Matrix không tính phần đó là capability của library, vì mục tiêu là tối ưu tổng lợi ích sau khi tính ownership.
