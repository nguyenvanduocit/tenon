Agent message parsing & rendering

T3 Code là reference mạnh nhất cho pipeline semantic đầy đủ; Orca là reference tốt nhất cho transcript fallback. libghostty-vt giải quyết terminal cells, không giải quyết agent message semantics.

Có thể dùng libghostty-vt, nhưng không dùng nó làm parser cho Agent Lens.

Dùng nó để Tenon chủ động render terminal trên macOS/mobile: cell grid, style, hyperlink, selection, damage, shell integration và graphics. Song song, xây một semantic pipeline độc lập theo hướng T3: provider/transcript adapter → canonical event → durable read model → các projection dành riêng cho conversation, work, approval, plan, diff và subagent.

T3 parse nhiều, render có chủ đích ít

Main timeline không phải event log. Projection chỉ trả về message, proposed plan, turn plan, work row/fold/toggle và working indicator.

Người dùng thực sự thấy

  • User bubble với Markdown, image/annotation/terminal context và review comments.
  • Assistant Markdown, copy/timestamp và changed-files checkpoint card.
  • Work row cho command, file change, MCP, approval/question và error.
  • Proposed plan, turn plan, working indicator, turn fold.
  • Subagent rollup ngắn; roster đầy đủ được chuyển sang Agents panel.

Bị ẩn, fold hoặc chuyển nơi khác

  • tool.started, phần lớn task.started/updated, tool.progress, context-window và checkpoint rows.
  • Agent-internal chatter và các work row cũ trong một turn.
  • System-role messages không có renderer trong TimelineRowContent.
  • Reasoning có ở provider contract nhưng không được biến thành main conversation message.
  • Auth/account/config/realtime/MCP status sống ở side state hoặc không có main-timeline component.

Orca: transcript fallback đơn giản và thực dụng

Orca chuẩn hóa Claude, Codex, Grok và OMP vào contract rất nhỏ: 5 roles, 4 content blocks. Nó render transcript tốt hơn status-only references, nhưng lifecycle/tool identity yếu hơn T3.

Canonical contract

userassistantreasoningtoolsystem

texttool-calltool-resultimage-ref

Mỗi message có ID, source priority, timestamp và optional turn ID. Source arbitration ưu tiên transcript hơn hook hơn scrape.

Decoder behavior

  • Claude: text/thinking/tool use/tool result/image; lọc injected meta/compact summary; tool-only user record trở thành role tool.
  • Codex: wrapped/unwrapped response items, event messages, reasoning, function/local shell/custom tools, image refs và interruption.
  • Grok: user/assistant/reasoning/backend tool; lọc bootstrap context và khôi phục pasted-image path.
  • OMP: message/custom message, thinking/tool calls/bash/python/file mention; content-addressed image blob chưa render; branch parents bị bỏ qua.

Terminal parser không phải agent parser

libghostty-vt và Alacritty bridge đều cho host quyền render grid rất sâu. Nhưng terminal protocol chỉ biết bytes, escape sequences, cells và shell markers — nó không biết đâu là assistant plan, approval request hay subagent task.

Herdr

libghostty-vt expose cells, style, hyperlink, semantic prompt/input/output và Kitty graphics. Agent state vẫn được suy ra từ bottom-of-buffer patterns: idle, working, blocked, unknown.

Kero

Alacritty bridge thêm OSC 7/9/22/777/133 interception và agent integration. HEAD chủ động bỏ progress inference từ terminal text; provider-reported status được coi là authority.

Supacode

Dùng OSC 3008 + hook/socket cho presence, notification, compacting và error. Đây là status transport tốt qua SSH, không phải transcript/message renderer.

Điều libghostty-vt thực sự mang lại cho mobile

Tenon có thể sở hữu surface và renderer: snapshot cell grid, damage-driven redraw, selection, links, images, accessibility projection và native gestures. Nhưng phần “giống Claude Code trên web” phải render từ semantic read model bên cạnh terminal surface, không phải OCR/scrape lại grid.

Tenon Agent Lens: nền móng đúng, coverage còn hẹp

Agent Lens đã có pure reducer, bounded storage, evidence model và protocol/transcript/hook sources. Đây là kiến trúc đáng mở rộng thay vì thay bằng một VT parser.

Giữ nguyên và nâng cấp

  • Evidence source, authority, freshness và byte/location anchors.
  • Pure AgentLensEvent → Snapshot reducer.
  • Transcript tail backpressure và bounded collections.
  • Context/instruction tách khỏi conversation timeline.
  • Protocol-native ưu tiên, transcript/hook là reconciliation/fallback.

Cần bổ sung

  • Stable turnID, itemID, requestID, taskID. ALR-001 done
  • Typed content blocks: text/markdown/image/file/ref/diff.
  • Plan/diff/task/token context đã typed; proposed-plan, checkpoint và compaction còn mở.
  • Typed approval/question decision và provider reply state.
  • Read projections cho Conversation, Work, Interactions, Changes, Agents và Context. ALR-002 done

Interaction boundary mapping cho Tenon

  • Provider/runtime facts đã xảy ra → EVENT.
  • Transcript/protocol body lớn hoặc stream sống lâu → RESOURCE / STREAM / TASK.
  • SwiftUI gọi application service cùng owner → typed DIRECT.
  • Finite request/reply qua plugin/CLI/agent boundary → INTENT; provider adapter cuối cùng gọi cùng typed service.

Không nên làm

  • Parse assistant/tool state từ terminal cells.
  • Để provider SDK types đi thẳng vào SwiftUI.
  • Persist từng text delta như một activity row.
  • Hiện mọi event trên main timeline.
  • Dùng PTY keystroke làm primary approval transport.
