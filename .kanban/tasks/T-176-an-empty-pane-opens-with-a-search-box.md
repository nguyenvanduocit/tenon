## Why

`docs/prds/command-surfaces.prd.md:157` already promises *"Shared LauncherMenu presentation
for `+`, tab secondary click, empty tab/slot/grid"*, and `:193` repeats it as an entry point.
The tree only half keeps it: empty **grid** space opens the search-first `LauncherMenu`
(`SpatialCanvasNSView.swift:410`), while an empty **tab** and an empty **pane** open
`EmptyStateCard` — a poster with a 58 pt icon badge, a title, a subtitle, and four fixed
tiles. Two presentations for one job, and the one a person meets most often is the one that
cannot be searched.

The operator asked for the decoration to go and a search box to take its place, and chose
the scope: the field also accepts a free shell command, so an empty pane is where
`npm run dev` is typed, not just where a view is picked.

## Design

- Query empty → the card keeps its grouped layout: primary **Add terminal**, *Start an
  agent*, *Open a view*, *Recently opened*, shortcut rule. Nothing is lost.
- Query typed → one flat ranked list replaces those groups, ↓/↑ walks it, Enter runs the
  highlighted row. Ranking is `CommandIndex.rank` — the palette's own matcher, not a second
  one.
- A typed query always offers a **run this as a command** row, placed by
  `RunCommandOffer`: leading when the query looks like a command line (it has inner
  whitespace or a shell-ish character), trailing when it is a single plain word — so `ch`
  still finds Changes first, while `npm run dev` is offered to run first.
- Enter has one owner: the field's `onSubmit`. The old `keyboardShortcut(.defaultAction)`
  on the Add-terminal button is removed, so the key cannot fire two paths.
- Running a command reuses the terminal delivery `AgentLaunchExecutor` already performs;
  that body moves to `TerminalCommandLaunch.run(commandLine:placement:…)` and the agent
  path calls it after its executable check. One path, correctly named.
